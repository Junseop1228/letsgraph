# Prompt Kit (prompt-kit)

근거: SRS v1.0 FR-PREM-03 · 결정 2026-10-27 (핵심 기능 = Prompt Kit) · 2026-11-16 (테마로 문항 배정, 팀의 문항별 추천 구조) · 조립: `lib/kit/build.ts` (AI 호출 없음) · 문항 배정: `lib/kit/plan.ts` · 화면: `app/(main)/analysis/posting/[id]/kit/`

## Requirements

### Requirement: FR-PREM-03 Prompt Kit 만들기
시스템은 공고 정리, 사업부 맥락, 연결 결과, 경험 카드를 묶어 사용자가 자기 AI에 붙여 넣을 Prompt Kit(`PromptKit`)을 만들고, 복사와 내려받기(마크다운, PDF)를 할 수 있게 해야 한다(SHALL). Kit은 검증된 조각만으로 조립하고 새 사실을 만들지 않는다. 프리미엄 기능이다.

#### Scenario: Kit 열기
- **WHEN** 공고 정리와 연결 결과가 있는 공고에서 Prompt Kit을 열면
- **THEN** 역할과 규칙, 공고(출처 표시, 주요 업무, 자격 요건, 우대 사항, 요구 역량, 주의사항), 사업부 맥락(공시 수치), 문항별 글쓰기 방식(저장된 지원서 문항이 있을 때만, FR-PREM-04), 전문성 근거, 에피소드, 빈 역량 지시, 진행 방식이 순서대로 들어간 키트가 보인다. 문항이 없으면 화면에 "지원서 문항을 붙여넣으면 문항마다 글쓰기 방식을 알려 드려요" 안내가 보이고, 키트는 그대로 복사할 수 있다

#### Scenario: 문항이 없을 때 (2026-11-17)
- **WHEN** 지원서 문항을 저장하지 않은 공고로 키트를 만들면
- **THEN** 일반 문항 유형별 가이드(네 유형)는 넣지 않는다. 키트에는 연결된 에피소드와 테마가 맞는 에피소드(유형마다 하나, 한 에피소드는 한 번)가 재료로 들어가고, 진행 방식은 "먼저 <에피소드>와 <전문성_근거>를 정리해 보여 주고, 실제 자소서 문항과 글자 수를 물어본 뒤, 문항마다 구조와 에피소드를 제안해 확인받고 진행하라"가 된다

#### Scenario: 전문성 근거 블록
- **WHEN** 연결 결과에 직무 전문성 ↔ 활동 연결이 있으면
- **THEN** 그 활동마다 `<전문성_근거 활동="...">`(기간, 맡은 역할, 사용한 데이터, 요약, 증명하는 역량별 이유)가 들어가고, "이 활동은 '이 역량이 있다'는 근거로만 쓰고, 장면과 행동은 <에피소드>에서 가져온다"고 적는다. 문항 가이드의 직무 역량에는 "전문성 근거 활동"이 함께 적힌다. 전문성을 증명하지 않는 활동의 내용은 넣지 않는다

#### Scenario: 에피소드 블록
- **WHEN** 키트에 에피소드가 들어가면
- **THEN** 에피소드마다 한 번만, 테마와 소속 활동 이름을 속성으로, 제목, 상황, 맡은 일, 행동, 결과, 배운 점, 연결된 역량별 이유가 들어간다. 활동의 요약이나 사용한 데이터는 넣지 않는다(에피소드에 필요한 사실은 대화 때 이미 에피소드에 담긴다)

#### Scenario: 진행 방식
- **WHEN** 사용자가 키트를 자기 AI에 붙여 넣으면
- **THEN** AI는 `<진행_방식>`대로 배정 검토 → 실제 문항과 글자 수 받기 → 문항 하나씩 칸마다 질문 → 잘된 점 1개와 고칠 점 최대 3개 피드백(대신 쓰지 않음) → 문항 간 중복 점검 순서로 코칭한다

#### Scenario: 복사·내려받기
- **WHEN** 사용자가 복사, 마크다운, PDF 중 하나를 누르면
- **THEN** 키트 전문이 클립보드에 들어가거나, `.md` 파일로 내려받아지거나, 인쇄 화면(가이드 없이 키트만)이 열린다

#### Scenario: 재료가 부족함
- **WHEN** 공고 정리나 연결 결과가 없는 공고에서 Kit을 열면
- **THEN** 둘 다 있어야 만들 수 있다고 알린다

### Requirement: FR-PREM-04 지원서 문항에 맞춘 키트
시스템은 사용자가 지원서 화면에서 복사해 붙인 글에서 실제 문항, 최대·최소 글자 수, 문항 유형을 읽고, 확인받은 뒤 공고에 저장해(`job_postings.questions`, 최대 10개) 키트를 그 문항에 맞춰야 한다(SHALL). 문항 유형은 직무 역량, 협업·갈등, 성장과정·가치관, 지원동기·입사 후 포부, 성과·강점, 경력기술서, 기타다. (`lib/kit/questions.ts`, AI: `extractQuestions`, 화면: `components/analysis/essay-questions.tsx`, `supabase/migrations/20261116040000_posting_questions.sql`)

#### Scenario: 문항 읽기
- **WHEN** 사용자가 키트 화면의 "지원서 문항"에 지원서 글을 붙여넣고 "문항 읽기"를 누르면
- **THEN** AI가 문항 문장('필수' 표시는 빼고 [회사명]은 남김), 최대 글자 수('0/5000' 등), 최소 글자 수('최소 500자 이상' 등, 붙어 있는 문항의 것), 유형을 읽고, 로그아웃 안내나 버튼 글자는 버린다. 붙여넣은 글은 데이터로만 다루고 AI로 보낸다는 안내가 미리 보인다

#### Scenario: 확인하고 저장
- **WHEN** 읽은 문항이 보이면
- **THEN** 사용자는 문항마다 유형을 고치거나 빼고 "이 문항으로 저장"을 누를 수 있고, 저장하면 키트가 다시 만들어진다. 최소 글자 수가 최대보다 크면 최소는 버린다

#### Scenario: 문항별 글쓰기 방식
- **WHEN** 저장된 문항이 있는 공고의 키트를 열면
- **THEN** `<문항_가이드>`가 일반 네 유형 대신 실제 문항 순서로 바뀌고, 문항마다 유형, 글자 수 제한, 구조, 실제 최대 글자 수로 계산한 단계별 분량(예: 5,000자 STAR면 S 약 1,000자), 최소 글자 수 안내, 쓸 재료, 강조할 점, 피할 것이 들어간다. 진행 방식은 실제 문항을 순서대로 진행하라고 바뀐다

#### Scenario: 문항 유형별 재료
- **WHEN** 문항별 재료를 고르면
- **THEN** 이야기 문항(직무 역량, 협업·갈등, 성장과정·가치관, 지원동기·포부)은 테마가 맞는 에피소드를, 성과·강점은 결과에 확인된 숫자가 있는 에피소드를 먼저 고른다. 한 에피소드는 한 문항에만 쓴다. 경력기술서는 직장 활동(인턴, 아르바이트, 없으면 모든 활동)을 `<경력_재료>`(기간, 맡은 역할, 요약, 강점 근거 에피소드)로 넣고, 키트가 모르는 부서·직급, 이직 사유, 정식 회사명은 "나에게 물어서 채워라"로 적는다. 기타는 코치가 구조를 먼저 제안하고 확인받게 한다

### Requirement: FR-PREM-05 문항과 에피소드를 내용으로 잇기
시스템은 저장된 지원서 문항 전체와 사용자의 에피소드 전체를 AI가 먼저 다 읽게 한 뒤, 문항마다 문항 문장이 실제로 묻는 것에 내용이 답하는 에피소드를 1개(꼭 필요하면 2개) 이어야 한다(SHALL). 테마는 참고만 하고 내용으로 판단하며, 한 에피소드는 한 문항에만 쓴다. 맞는 에피소드가 없으면 비워 두고 필요한 장면을 적는다. 결과는 문항과 함께 저장된다(`questions[].episodeIds`, `fit`, `need`, `manual`). (AI: `matchQuestions`, 다듬기: `applyMatches` in `lib/kit/questions.ts`)

#### Scenario: 저장하면서 잇기
- **WHEN** 사용자가 지원서 문항을 저장하면
- **THEN** AI가 문항과 에피소드를 이어 함께 저장하고, 문항마다 이어진 에피소드와 이유(또는 "맞는 에피소드가 없어요"와 필요한 장면, 만들기로 가는 링크)가 보인다. AI가 실패하면 문항은 그대로 저장되고 에피소드는 테마로 배정한다

#### Scenario: 테마를 넘어 내용으로
- **WHEN** 문항이 특정 장면을 묻는데(예: 고객의 입장, 예상치 못한 위기) 그 장면이 다른 테마의 에피소드에 있으면
- **THEN** 그 에피소드를 잇는다. 유형이 기타인 문항에도 에피소드를 잇는다

#### Scenario: 다듬기
- **WHEN** AI가 결과를 돌려주면
- **THEN** 없는 에피소드는 버리고, 문항 순서대로 이미 쓴 에피소드는 다시 쓰지 않으며, 문항당 2개까지만 남긴다. 경력기술서 문항은 에피소드 없이 활동(경력 재료)으로 쓴다

#### Scenario: 직접 바꾸기와 다시 잇기
- **WHEN** 사용자가 문항의 "다른 에피소드로"에서 에피소드나 "에피소드 없이 쓰기"를 고르면
- **THEN** 그 문항은 직접 고른 것으로 저장되고(다시 이어도 바뀌지 않음), 그 에피소드는 다른 문항에서 빠진다. "AI 추천으로 되돌리기"는 그 문항을 다시 AI에게 맡긴다. "에피소드 다시 잇기"는 새로 만든 에피소드까지 읽어 직접 고르지 않은 문항을 다시 잇는다

#### Scenario: 키트에 반영
- **WHEN** 이어진 문항이 있는 키트를 만들면
- **THEN** 문항 가이드에 쓸 에피소드(번호와 제목, 둘째 에피소드), "이 에피소드인 이유", 또는 "필요한 장면: ... 지어내지 말고 질문해서 찾아라"가 들어간다

### Requirement: FR-PREM-06 키트 재료를 하나로, 최신으로 (2026-11-17)
시스템은 지원서 문항이 있으면 문항에 쓰는 에피소드만 키트에 넣고, 문항 연결이 역량 연결을 참고하게 하며, 결과가 예전 카드 기준이면 알려야 한다(SHALL).

#### Scenario: 문항에 쓰는 에피소드만
- **WHEN** 저장된 문항이 있는 공고로 키트를 만들면
- **THEN** `<에피소드>`에는 문항에 이어진(또는 테마로 배정된) 에피소드만 들어가고, 공고 역량과 이어졌지만 어느 문항에도 안 쓰인 에피소드는 `<남은_재료>`에 제목과 역량만 적어 "더 맞는 문항이 있으면 제안하라"고 한다

#### Scenario: 문항 연결이 역량 연결을 참고
- **WHEN** 문항과 에피소드를 이으면
- **THEN** AI에 에피소드마다 이미 이어진 공고 역량(`linkedCompetencies`)을 함께 보내고, 문항이 그 역량을 묻고 장면이 맞을 때 그 에피소드를 먼저 고려하게 한다

#### Scenario: 오래된 결과 안내
- **WHEN** 연결 결과나 문항 연결을 만든 뒤 카드가 바뀌었으면
- **THEN** 키트 화면에 "연결 결과 다시 만들기"(연결 화면으로) 안내, 지원서 문항 칸에 "“에피소드 다시 잇기”를 누르면 지금 카드로 다시 이어요" 안내가 보인다. 문항 연결에는 그때 읽은 에피소드의 지문(`questions[].basis`)이 저장된다

### Requirement: FR-PREM-03a 프롬프트 키트 = 지원 근거 묶음 (2026-11-17, 키트의 목표를 바꿈; 2026-11-18 이름은 "프롬프트 키트"로 유지하기로 함)
키트는 자소서를 어떻게 쓰라는 안내가 아니라, 공고 조건마다 근거가 될 내 활동·에피소드를 모은 묶음이어야 한다(SHALL). 사용자는 원하는 AI에 붙여넣고 글은 자기 방식대로 쓴다. 위의 문항 가이드, 진행 방식, 지원서 문항 관련 시나리오(FR-PREM-04 ~ 06)는 키트에서 쓰지 않는다(코드는 남아 있음, 보류).

#### Scenario: 키트 구성
- **WHEN** 지원 근거가 있는 공고로 키트를 열면
- **THEN** `<규칙>`(없는 사실·수치 금지, 근거 없음·약함을 다른 카드로 억지로 채우지 않기), `<공고>`, `<사업부_맥락>`(있을 때), `<지원_근거>`(조건 종류별로 조건, 근거 강도, 추천 카드 번호, 이유, 부족한 점, 할 일), 추천된 `<활동 id="A1">`(기간, 역할, 사용한 데이터, 요약)과 `<에피소드 id="E1">`(상황, 맡은 일, 행동, 결과, 배운 점)이 순서대로 들어간다. 추천 카드는 한 번씩만 들어가고, 구조·글자 수 같은 글쓰기 지시는 없다

#### Scenario: 키트 화면
- **WHEN** 키트 화면을 열면
- **THEN** 제목은 "프롬프트 키트", 왼쪽에 조건별 추천(근거 강도, 추천 카드, 부족한 점, 할 일)과 "카드 상세와 이유 보기", 오른쪽에 복사·내려받기·인쇄할 수 있는 키트 미리보기가 보인다. 경력 요건 안내와 오래된 결과 안내는 그대로 보인다

#### Scenario: 문항과 글자 수 (BM 제안서 2026-11-18, FR-PREM-03a에 더함)
- **WHEN** 사용자가 키트 화면에서 지원서 문항을 붙여 넣어 저장했으면(FR-PREM-04, 문항 ↔ 에피소드 매칭 FR-PREM-05)
- **THEN** 키트에 `<문항>` 블록이 공고·사업부 다음, 지원 근거 앞에 들어간다: 문항마다 "[문항 n] 문항 (n자 이상, n자 이내)", 짝지어진 에피소드(E번호)와 이유, 맞는 에피소드가 없으면 "없음 (필요한 장면: …)". 짝지어진 에피소드는 조건별 추천에 없더라도 E번호 카드로 키트에 담긴다. 규칙에 "문항마다 글자 수를 지켜라. 어울리는 에피소드가 없는 문항은 지어내지 말고 나에게 물어라."가 들어간다. 문항이 없으면 블록도 규칙 줄도 없다. 글자 수 배분이나 문단 구조 같은 작성 지도는 여전히 넣지 않는다. 키트 화면 왼쪽 위에 문항 붙여넣기·저장·다시 매칭(카드가 바뀌면 안내)이 다시 보인다
