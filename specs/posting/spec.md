## Requirements

### Requirement: FR-POST-01 공고 정리
시스템은 사용자가 올린 채용공고 PDF를 읽어 주요 업무, 자격 요건, 우대 사항, 요구 역량, 마감일, 작성 주의사항을 정리하고, 공고에 적힌 역량(명시)과 AI가 추론한 역량(추론)을 구분해 보여줘야 한다(SHALL). 쿼터가 적용된다.

#### Scenario: 공고 올리기
- **WHEN** 로그인한 사용자가 공고 탭 위쪽 "공고 추가"에서 10MB 이하 PDF를 올리고 "공고 정리하기"를 누르면
- **THEN** AI 결과를 형식 검증한 뒤 공고와 정리 결과를 저장하고, 쿼터 1회를 쓰고, 공고 분석 결과 화면으로 이동한다

#### Scenario: 올리기 전 안내
- **WHEN** 사용자가 업로드 칸을 보면
- **THEN** 파일을 생성형 AI로 보낸다는 사실과 원본을 저장하지 않는다는 안내가 함께 보인다

#### Scenario: 잘못된 파일
- **WHEN** PDF가 아니거나 10MB를 넘는 파일을 올리면
- **THEN** 분석하지 않고 이유를 한 문장으로 알린다

#### Scenario: AI 실패 (EX-03)
- **WHEN** AI 응답이 30초를 넘기거나 형식 검증에 실패하면
- **THEN** 실패를 알리고 쿼터는 차감하지 않는다

#### Scenario: 공고 본문 없음
- **WHEN** AI가 입력에 실제 공고 본문(맡을 업무, 자격 요건)이 없고 사이트 메뉴나 공통 안내 문구뿐이라고 판단하거나, 정리 결과에 업무나 역량이 하나도 없으면
- **THEN** 공고를 저장하지 않고 쿼터도 쓰지 않으며, 입력 경로에 맞는 다음 방법(주소면 붙여넣기나 PDF, 붙여넣기면 업무·자격 요건까지 붙여넣기, 파일이면 공고 파일인지 확인)을 한 문장으로 알린다

#### Scenario: 공고 정리 보기
- **WHEN** 사용자가 공고 분석 결과 화면(`/postings/[id]`)을 열면
- **THEN** AI 정리 라벨, 공고 명시 / 업무상 추론 라벨로 나뉜 요구 역량, 작성 주의사항, "이 직무의 위치"(직무 → 기업 → 사업부와 사업부 수치)가 보이고, "내 경험과 연결 보기"로 연결 탭에 간다

#### Scenario: 데모 공고
- **WHEN** 키가 연결되지 않은 상태에서 공고 탭을 열면
- **THEN** "데모용 예시 공고"로 표시된 공고로 전체 흐름을 볼 수 있고, 업로드는 연결 전이라고 알린다

### Requirement: POST-03 공고 주소로 정리하기
시스템은 사용자가 넣은 채용공고 주소에서 그 페이지 하나만 가져와 FR-POST-01과 같은 정리를 해야 한다(SHALL). 가져오는 것은 사용자가 넣은 페이지와, 본문이 프레임으로 들어 있는 경우 그 페이지에 박힌 프레임(최대 3개)뿐이며, 다른 링크를 따라가거나 예약해서 모으지 않는다(NFR-EXT-02). 공개된 http/https 주소만 받고, 이동(리다이렉트)과 프레임마다 다시 검사해 사설·내부 주소로는 요청하지 않는다. 가져온 본문은 데이터로만 다루고 그 안의 지시는 따르지 않는다. 쿼터가 적용된다.

#### Scenario: 주소 넣기
- **WHEN** 로그인한 사용자가 공고 탭 "공고 추가"에 공고 페이지 주소를 넣고 "주소로 정리하기"를 누르면
- **THEN** 그 페이지의 본문(웹 페이지 글, PDF, 이미지)을 AI로 정리하고 형식 검증한 뒤, 공고(`source` = `url`, 넣은 주소)와 정리 결과를 저장하고, 쿼터 1회를 쓰고, 공고 분석 결과 화면으로 이동한다

#### Scenario: 넣기 전 안내
- **WHEN** 사용자가 주소 칸을 보면
- **THEN** 넣은 주소의 페이지 한 개만 가져와 생성형 AI로 보낸다는 안내와, 로그인이 필요하거나 이미지로만 된 공고는 읽지 못할 수 있다는 안내가 보인다

#### Scenario: 받을 수 없는 주소
- **WHEN** 주소 형식이 틀렸거나, http/https가 아니거나, localhost·사설 주소·내부 주소를 가리키면
- **THEN** 아무것도 가져오지 않고 이유를 한 문장으로 알린다

#### Scenario: 본문을 읽지 못함
- **WHEN** 페이지가 로그인을 요구하거나(401/403), 10초 안에 응답하지 않거나, 5MB를 넘거나, 읽을 수 있는 본문이 200자보다 짧으면
- **THEN** 정리하지 않고 쿼터도 쓰지 않으며, 공고 내용을 붙여넣거나 PDF로 올리라고 안내한다

#### Scenario: 자바스크립트로 공고를 불러오는 페이지
- **WHEN** 가져온 페이지에 사이트 메뉴와 공통 안내 문구만 있고 공고 본문은 자바스크립트가 나중에 불러오면 (예: 일부 기업 채용 사이트)
- **THEN** FR-POST-01 "공고 본문 없음"에 따라 저장하지 않고, 사이트 내부 API를 따로 호출하지 않는다

### Requirement: POST-04 공고 내용 붙여넣기
시스템은 주소로 읽히지 않는 공고(자바스크립트로 불러오는 페이지, 로그인이 필요한 페이지)를 위해 사용자가 공고 페이지에서 복사한 글을 붙여넣으면 FR-POST-01과 같은 정리를 해야 한다(SHALL). 붙여넣은 글은 데이터로만 다루고, 공고는 `source` = `upload`로 저장한다. 쿼터가 적용된다.

#### Scenario: 붙여넣기
- **WHEN** 로그인한 사용자가 "공고 내용 붙여넣기" 칸에 공고 글을 붙여넣고 "붙여넣은 내용으로 정리하기"를 누르면
- **THEN** AI로 정리하고 형식 검증한 뒤 저장하고, 쿼터 1회를 쓰고, 공고 분석 결과 화면으로 이동한다

#### Scenario: 너무 짧거나 긴 글
- **WHEN** 붙여넣은 글이 100자보다 짧거나 2만 자보다 길면
- **THEN** 정리하지 않고 이유를 한 문장으로 알린다

#### Scenario: 붙여넣기 전 안내
- **WHEN** 사용자가 붙여넣기 칸을 보면
- **THEN** 전체 선택 후 복사해 붙여넣는 방법, 메뉴가 섞여도 된다는 것, 내용을 생성형 AI로 보낸다는 안내가 보인다

### Requirement: POST-02 공고 달력
시스템은 공고 탭의 첫 화면에서 저장한 공고를 마감일 기준 달력과 상태(관심, 지원, 면접, 합격, 불합격)로 보여주고, 목록 보기에서는 마감·상태로 정렬하고 상태로 거를 수 있게 해야 한다(SHALL). D-day는 서울 시간 기준이다.

#### Scenario: 이번 달 달력
- **WHEN** 사용자가 공고 탭을 열면
- **THEN** 이번 달 칸에 마감 공고가 상태 표시와 함께 놓이고, 오늘 날짜가 강조되며, 마감일 미정 공고와 상태 요약이 옆에 보인다

#### Scenario: 내 공고 표: 상태로 거르기와 마감 순 정렬
- **WHEN** 사용자가 "목록"을 누르면
- **THEN** 마감이 가까운 순(마감일 미정은 마지막)으로 표가 나오고, 상태 버튼으로 거를 수 있으며, 맞는 공고가 없으면 "이 상태의 공고가 없어요."를 보여준다

### Requirement: POST-05 공고와 회사·사업부 잇기
시스템은 사용자가 올린 공고의 회사명을 카탈로그 기업과 맞추고, 공고가 분명히 보여 줄 때 그 직무가 속한 사업부를 정해 공고에 저장해야 한다(SHALL, `job_postings.company_id`, `segment_id`). 이것이 연결 결과와 Prompt Kit의 사업부 맥락이 된다. 확실하지 않으면 비워 둔다. 맞추기에 실패해도 공고 정리는 막지 않는다. (`lib/posting/company.ts`, `lib/posting/segment.ts`, AI: `pickSegment`)

#### Scenario: 회사 맞추기
- **WHEN** 공고를 정리하면
- **THEN** 회사명을 "(주)", "주식회사", 띄어쓰기, 대소문자를 무시하고 카탈로그 기업 이름과 정확히 맞추고, 아니면 공고 회사명이 시작하는 가장 긴 기업 이름을 고른다(예: "CJ제일제당 식품사업부문" → CJ제일제당). 그 밖에는 짐작하지 않는다

#### Scenario: 사업부 고르기
- **WHEN** 맞춘 기업에 사업부가 하나면 그 사업부를, 여럿이면 AI가 공고의 직무 제목과 업무를 보고 하나를 고르고
- **THEN** 공고만으로 분명하지 않으면 사업부를 비워 둔다. AI가 준 id는 그 기업의 사업부인지 확인한 뒤에만 쓴다

#### Scenario: 예전에 올린 공고
- **WHEN** 사업부가 비어 있는 공고로 연결 결과를 만들면
- **THEN** 그때 한 번 회사와 사업부를 맞춰 공고에 저장하고 사업부 맥락으로 쓴다
