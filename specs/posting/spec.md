# 공고 (posting)

근거: SRS v1.0 FR-POST-01 · 결정 2026-11-10 (공고 PDF 업로드), 2026-11-09 (공고는 외부에서 가져와 서비스 안에서 가공), NFR-EXT-02 (채용 플랫폼 크롤링 금지) · 계약: `lib/contracts/activity.ts` (`JobPosting`, `PostingAnalysisOutput`) · AI: `lib/ai/tasks.ts` · 화면: `app/(main)/analysis/`, `app/(main)/manage/` (달력)

> OPEN: 공고 자동 수집 경로 (개인 이용 가능한 민간 공고 API 없음, 2026-11-10).

## Requirements

### Requirement: FR-POST-01 공고 정리
시스템은 사용자가 올린 채용공고 PDF를 읽어 주요 업무, 자격 요건, 우대 사항, 요구 역량, 마감일, 작성 주의사항을 정리하고, 공고에 적힌 역량(명시)과 AI가 추론한 역량(추론)을 구분해 보여줘야 한다(SHALL). 쿼터가 적용된다.

#### Scenario: 공고 올리기
- **WHEN** 로그인한 사용자가 10MB 이하 PDF를 올리고 "공고 정리하기"를 누르면
- **THEN** AI 결과를 형식 검증한 뒤 공고와 정리 결과를 저장하고, 쿼터 1회를 쓰고, 공고 정리 화면으로 이동한다

#### Scenario: 올리기 전 안내
- **WHEN** 사용자가 업로드 칸을 보면
- **THEN** 파일을 생성형 AI로 보낸다는 사실과 원본을 저장하지 않는다는 안내가 함께 보인다

#### Scenario: 잘못된 파일
- **WHEN** PDF가 아니거나 10MB를 넘는 파일을 올리면
- **THEN** 분석하지 않고 이유를 한 문장으로 알린다

#### Scenario: AI 실패 (EX-03)
- **WHEN** AI 응답이 30초를 넘기거나 형식 검증에 실패하면
- **THEN** 실패를 알리고 쿼터는 차감하지 않는다

#### Scenario: 공고 정리 보기
- **WHEN** 사용자가 공고 정리 화면을 열면
- **THEN** AI 정리 라벨, 공고 명시 / 업무상 추론 라벨로 나뉜 요구 역량, 작성 주의사항, "이 직무의 위치"(직무 → 기업 → 사업부와 사업부 수치)가 보인다

#### Scenario: 데모 공고
- **WHEN** 키가 연결되지 않은 상태에서 분석 탭을 열면
- **THEN** "데모용 예시 공고"로 표시된 공고로 전체 흐름을 볼 수 있고, 업로드는 연결 전이라고 알린다

### Requirement: POST-02 공고 달력
시스템은 저장한 공고를 마감일 기준 달력과 상태(관심, 지원, 면접, 합격, 불합격)로 보여줘야 한다(SHALL). D-day는 서울 시간 기준이다.

#### Scenario: 이번 달 달력
- **WHEN** 사용자가 관리 > 마감 달력을 열면
- **THEN** 이번 달 칸에 마감 공고가 상태 표시와 함께 놓이고, 오늘 날짜가 강조되며, 마감일 미정 공고와 상태 요약이 옆에 보인다
