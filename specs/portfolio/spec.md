# 경험 (portfolio)

근거: SRS v1.0 FR-PREM-01 · 결정 2026-10-27 (형식 없는 포트폴리오), 2026-11-09 (pdf, docx, pptx, GitHub 링크; hwp 제외; 자기소개서 포함; 경험 카드로 변환), 2026-11-10 (업로드 파일 처리 규칙: 본인만, 원본 PDF 삭제) · 계약: `lib/contracts/activity.ts` (`Experience`, `ExperienceExtractionOutput`) · AI: `lib/ai/tasks.ts`, `lib/ai/chat.ts` · 화면: `app/(main)/manage/` (경험 카드, 경험 대화)

## Requirements

### Requirement: FR-PREM-01 경험 카드 만들기
시스템은 사용자가 올린 포트폴리오와 자기소개서에서 경험(`Experience`)을 추출해 경험 카드(상황·행동·결과·역량)로 보여주고, 사용자가 고치고 지울 수 있게 해야 한다(SHALL). 파일을 AI로 보낸다는 사실을 올리기 전에 알리고, 원본 파일은 저장하지 않는다. 쿼터가 적용된다.

#### Scenario: PDF로 경험 카드 만들기
- **WHEN** 로그인한 사용자가 관리 > 경험 카드에서 PDF를 올리면
- **THEN** AI 결과를 형식 검증한 뒤 경험 카드로 저장하고, 몇 장을 만들었는지와 원본을 저장하지 않았다는 사실을 알린다

#### Scenario: 수치를 지어내지 않음
- **WHEN** 원문에 결과 수치가 없으면
- **THEN** 카드의 결과 칸은 "수치는 직접 확인해서 넣어요"로 남는다

#### Scenario: 카드 보기
- **WHEN** 사용자가 경험 카드 탭을 열면
- **THEN** 출처(파일·활동)별로 묶인 카드가 종류, 기간, 상황·행동·결과, 역량 태그와 함께 보인다

> 아직 구현 전: 카드 고치기·지우기, docx·pptx·GitHub 링크 입력(지금은 PDF만).

### Requirement: PORT-02 경험 대화
시스템은 대화로 경험을 보충하고, 대화 끝에 경험 카드 초안을 요약해 보여준 뒤 저장할지 묻게 해야 한다(SHALL). AI는 한 번에 질문 하나만 하고, 사용자가 말하지 않은 사실을 만들지 않는다.

#### Scenario: 대화로 경험 정리
- **WHEN** 사용자가 관리 > 경험 대화에서 답을 보내면
- **THEN** AI 코치(보라색 표시)가 상황 → 역할 → 행동 → 결과 중 빠진 것을 하나씩 묻는다

#### Scenario: 카드 초안과 저장
- **WHEN** 두 번 이상 답한 사용자가 "카드 초안 만들기"를 누른 뒤 "경험 카드로 저장"을 누르면
- **THEN** AI 요약 라벨이 붙은 초안이 먼저 보이고, 저장하면 출처가 "경험 대화"인 경험 카드가 생긴다

#### Scenario: 데모 모드
- **WHEN** AI 키가 연결되지 않았으면
- **THEN** 정해진 질문 순서로 답하고, 초안은 사용자가 쓴 문장만 칸에 나눠 담으며, 저장은 하지 않는다고 알린다
