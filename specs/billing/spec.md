# 이용 등급·결제 (billing)

근거: SRS v1.0 FR-ACCT-03, FR-ACCT-04, EX-03, EX-04, EX-05 · 결정 2026-11-09 PAYMENT (토스페이먼츠 테스트 모드, API 개별 연동 키, 일반 결제) · 결정 '쿼터는 LLM 비용 기능에만' · 계약: `lib/contracts/billing.ts` (주문·결제 상태, 패스 종류), `supabase/migrations/` (주문, 결제 기록, 패스, 쿼터 사용)

이용 등급(`Plan`)은 `free`와 `premium` 두 가지예요(기관 등급은 범위 밖). 패스 종류(`PassType`)는 `season`(기간제)과 `single`(건당)이에요.

> OPEN: 패스 가격, 기간, 건당 횟수, 무료 월 쿼터 숫자 (가격 정책 담당: 팀원). 정해지면 `lib/contracts/billing.ts`의 상수만 바꿔요.

## Requirements

### Requirement: FR-ACCT-03 패스 구매
시스템은 로그인한 사용자가 패스를 고르고 토스페이먼츠로 결제하면, 결제 결과를 서버에서 확인한 뒤에만 패스를 부여해야 한다(SHALL). 금액은 서버에 저장한 주문 금액과 같을 때만 승인하고, 승인과 부여는 같은 주문에 대해 한 번만 일어나야 한다.

결제 상태 (`PaymentStatus`, 코드와 같은 값):

| 상태 | 뜻 | 다음 상태 |
|---|---|---|
| `created` | 주문 생성 (주문번호, 금액, 패스 종류 저장) | `pending` |
| `pending` | 사용자가 결제창에 있음 | `confirming`, `canceled` |
| `confirming` | 성공 리다이렉트를 받아 금액 확인 후 승인 API 호출 중 | `paid`, `failed` |
| `paid` | 승인 완료 | `granted`, `grant_failed` |
| `granted` | 패스 부여 완료 (끝) | — |
| `canceled` | 사용자 취소 또는 실패 리다이렉트 (끝) | — |
| `failed` | 승인 거절·금액 불일치·오류 (끝) | — |
| `grant_failed` | 돈은 냈는데 부여 실패, 운영자 확인 대상 | `granted` (운영자 처리) |

#### Scenario: 패스 화면
- **WHEN** 사용자가 패스 화면을 열면
- **THEN** 시즌 패스와 건당 패스가 나란히 보이고, 결제 버튼은 시즌 패스만 검정(주요), 건당 패스는 보조 버튼이다. 무료로도 AI 기능(공고 정리, 카드 만들기, 연결 결과)을 합쳐 한 달에 3번 쓸 수 있다는 문장과, 시즌 패스의 "AI 기능 월 30회 (무료는 3회)"가 보인다

#### Scenario: 정상 결제
- **WHEN** 사용자가 시즌 패스를 골라 결제창에서 결제를 마치고 성공 주소로 돌아오면
- **THEN** 서버가 금액을 확인하고 승인 API를 호출해 상태가 `paid` → `granted`가 되고, 화면에 프리미엄 기능을 쓸 수 있다고 표시된다

#### Scenario: 결제 취소·실패 (E1)
- **WHEN** 사용자가 결제창을 닫거나 실패 주소로 돌아오면
- **THEN** 상태가 `canceled`가 되고 패스는 부여되지 않으며, 다시 시도할 수 있다

#### Scenario: 금액 위조
- **WHEN** 성공 주소의 금액이 저장된 주문 금액과 다르면
- **THEN** 승인 API를 부르지 않고 상태가 `failed`가 된다

#### Scenario: 같은 주문을 두 번 승인 시도
- **WHEN** 성공 주소가 새로고침 등으로 두 번 호출되면
- **THEN** 두 번째 호출은 아무것도 바꾸지 않고 현재 상태를 보여준다

#### Scenario: 결제는 됐는데 부여 실패 (E2)
- **WHEN** 승인은 성공했는데 패스 저장이 실패하면
- **THEN** 상태가 `grant_failed`로 기록되어 운영자가 확인할 수 있고, 사용자에게는 확인 중이라고 알린다

### Requirement: FR-ACCT-04 이용 현황 보기
시스템은 로그인한 사용자에게 이용 등급, 이번 달 남은 쿼터, 가진 패스(종류, 남은 기간이나 횟수)를 현재 값으로 보여주고, 쿼터를 늘리는 방법(패스)을 함께 보여줘야 한다(SHALL).

#### Scenario: 이용 현황 열기
- **WHEN** 로그인한 사용자가 이용 현황을 열면
- **THEN** 등급, 남은 쿼터, 패스 정보가 표시된다. 쿼터를 쓰는 기능(공고 정리, 카드 만들기, 연결 결과)과 Prompt Kit은 쿼터를 쓰지 않는다는 사실이 한 문장으로 보인다

#### Scenario: 로그인한 계정과 로그아웃
- **WHEN** 로그인한 사용자가 위쪽 프로필 아이콘으로 내 계정을 열면
- **THEN** 어느 계정으로 로그인했는지(Google 계정 또는 이메일과 주소)와 "로그아웃" 버튼이 맨 위에 보인다. 헤더에는 로그아웃 버튼을 두지 않는다(2026-11-16 디자인 감사)

### Requirement: BILL-01 쿼터 차감
시스템은 LLM 비용이 드는 기능(공고 정리, 경험 추출, 연결 결과, Prompt Kit)을 쓸 때만 쿼터를 차감하고, AI 분석이 실패하면 차감하지 않아야 한다(SHALL).

#### Scenario: 쿼터 소진 (EX-04)
- **WHEN** 남은 쿼터가 없는 무료 사용자가 공고 정리를 요청하면
- **THEN** 분석하지 않고 패스로 쿼터를 늘리는 방법을 안내한다

#### Scenario: AI 실패 시 쿼터 유지 (EX-03)
- **WHEN** AI 응답이 30초를 넘기거나 출력 검증에 실패하면
- **THEN** 실패를 알리고 다시 시도할 수 있게 하며 쿼터는 그대로다

#### Scenario: 프리미엄 전용 기능 (EX-05)
- **WHEN** 무료 사용자가 프리미엄 전용 기능을 요청하면
- **THEN** 무료로 볼 수 있는 범위를 보여주고 패스 구매를 안내한다
