# 계정 (account)

근거: SRS v1.0 FR-ACCT-01, FR-ACCT-05, 5.0 공통 예외 EX-01 · 결정 2026-11-09 LOGIN · 계약: `supabase/migrations/` (프로필·동의 기록, 권한), `lib/contracts/account.ts` · 화면: `app/auth/`, `app/(main)/manage/` (이용 현황 > 회원 탈퇴)

## Requirements

### Requirement: FR-ACCT-01 회원 가입·로그인
시스템은 구글, 카카오, 이메일 세 가지 방법으로 가입과 로그인을 할 수 있게 해야 한다(SHALL). 처음 로그인한 사용자에게는 계정을 만들기 전에 이용약관, 개인정보 수집 항목, 생성형 AI 사용 사실을 알리고 동의를 받아야 한다.

#### Scenario: 처음 로그인하고 동의함
- **WHEN** 계정이 없는 사용자가 구글로 인증을 마치고 필수 항목 세 가지에 모두 동의하면
- **THEN** 무료 등급(`Plan = free`) 계정이 만들어지고, 동의 항목과 동의 시각이 기록되고, 원래 보던 화면으로 돌아간다

#### Scenario: 필수 동의를 하지 않음
- **WHEN** 처음 로그인한 사용자가 필수 항목 중 하나라도 동의하지 않고 나가면
- **THEN** 계정(프로필)은 만들어지지 않고, 다음 로그인 때 동의 단계가 다시 나온다

#### Scenario: 간편 로그인 실패·취소
- **WHEN** 사용자가 구글이나 카카오 인증 화면에서 취소하거나 인증이 실패하면
- **THEN** 로그인 화면으로 돌아오고, 무엇이 실패했는지 한 문장으로 알려준다

#### Scenario: 로그인이 필요한 기능을 누름 (EX-01)
- **WHEN** 로그인하지 않은 사용자가 로그인이 필요한 기능을 누르면
- **THEN** 로그인 화면으로 안내하고, 로그인을 마치면 누르려던 화면으로 돌아온다

#### Scenario: 로그인 전 관심 정보 합치기
- **WHEN** 로그인 전에 직무 카드로 관심 정보를 만든 사용자가 로그인하면
- **THEN** 그 관심 정보(`InterestProfile`)가 계정에 합쳐진다

> 아직 구현 전: 로그인 전 관심 정보 합치기, 카카오 로그인. PROPOSED: 구현 순서는 구글 → 이메일 → 카카오. 이메일 인증 메일은 별도 SMTP로 보낸다(SMTP 종류는 구현 때 결정). 카카오는 비즈 앱 전환과 이메일 동의항목 심사가 필요하다.

### Requirement: FR-ACCT-05 회원 탈퇴
시스템은 사용자가 탈퇴할 수 있게 하고, 탈퇴하면 법령상 보관해야 하는 결제 기록(주문, `orders`의 사용자 연결만 끊음)만 남긴 뒤 나머지 계정 정보와 개인정보를 지워야 한다(SHALL).

#### Scenario: 탈퇴 확인
- **WHEN** 로그인한 사용자가 관리 > 이용 현황 > 회원 탈퇴에서 지워지는 정보(관심 정보·관심 기업, 공고·공고 정리, 경험 카드·경험 대화, 연결 결과·Prompt Kit, 남은 패스·쿼터)를 보고 "탈퇴합니다"를 입력해 확인하면
- **THEN** 계정과 사용자 데이터가 모두 지워지고(결제 기록은 사용자 연결 없이 보관), 로그아웃되어 탐색 화면으로 간다

#### Scenario: 탈퇴 취소
- **WHEN** 사용자가 취소를 누르거나 확인 문구를 다르게 입력하면
- **THEN** 아무것도 지워지지 않는다

### Requirement: 로그인하지 않은 방문자 (2026-11-18)
시스템은 계정 저장소(Supabase)가 켜진 환경에서 로그인하지 않은 방문자에게 개인 데이터를 보여 주지 않아야 한다(SHALL). 예전처럼 데모 데이터를 보여 주지도 않는다. 데모 데이터는 계정 저장소가 꺼진 환경(로컬 개발, 자동 시험)에서만 쓴다. (`lib/data/index.ts`의 `userData`가 `guest: true`와 빈 데이터를 돌려준다, `components/lg/login-prompt.tsx`)

#### Scenario: 개인 화면
- **WHEN** 로그인하지 않은 방문자가 공고, 공고 상세, 관리, 연결, 지원 근거, 프롬프트 키트, 내 계정을 열면
- **THEN** 그 화면 대신 화면별 로그인 안내(무엇을 할 수 있는지 한 문장, 로그인·회원가입 버튼, 로그인 후 돌아올 주소)와 "직무 지도와 기업 정보는 로그인 없이도 볼 수 있어요"가 보인다

#### Scenario: 공용 화면
- **WHEN** 로그인하지 않은 방문자가 탐색(직무 지도)과 기업·사업부 화면을 열면
- **THEN** 지금처럼 볼 수 있고, 관심 기업이나 공고 마감 알림 같은 개인 부분은 비어 있다. AI를 쓰거나 저장하는 동작은 로그인 화면으로 보낸다(BILL-01a)
