# 계정 (account)

근거: SRS v1.0 FR-ACCT-01, FR-ACCT-05, 5.0 공통 예외 EX-01 · 결정 2026-11-09 LOGIN · 계약: `supabase/migrations/` (프로필·동의 기록), `lib/contracts/account.ts`

## Requirements

### Requirement: FR-ACCT-01 회원 가입·로그인
시스템은 구글, 카카오, 이메일 세 가지 방법으로 가입과 로그인을 할 수 있게 해야 한다(SHALL). 처음 로그인한 사용자에게는 계정을 만들기 전에 이용약관, 개인정보 수집 항목, 생성형 AI 사용 사실을 알리고 동의를 받아야 한다.

#### Scenario: 처음 로그인하고 동의함
- **WHEN** 계정이 없는 사용자가 구글로 인증을 마치고 필수 항목 세 가지에 모두 동의하면
- **THEN** 무료 등급(`Plan = free`) 계정이 만들어지고, 동의 항목과 동의 시각이 기록되고, 원래 보던 화면으로 돌아간다

#### Scenario: 필수 동의를 하지 않음
- **WHEN** 처음 로그인한 사용자가 필수 항목 중 하나라도 동의하지 않고 나가면
- **THEN** 계정(프로필)은 만들어지지 않고, 다음 로그인 때 동의 단계가 다시 나온다

#### Scenario: 간편 로그인 실패·취소
- **WHEN** 사용자가 구글이나 카카오 인증 화면에서 취소하거나 인증이 실패하면
- **THEN** 로그인 화면으로 돌아오고, 무엇이 실패했는지 한 문장으로 알려준다

#### Scenario: 로그인이 필요한 기능을 누름 (EX-01)
- **WHEN** 로그인하지 않은 사용자가 로그인이 필요한 기능을 누르면
- **THEN** 로그인 화면으로 안내하고, 로그인을 마치면 누르려던 화면으로 돌아온다

#### Scenario: 로그인 전 관심 정보 합치기
- **WHEN** 로그인 전에 직무 카드로 관심 정보를 만든 사용자가 로그인하면
- **THEN** 그 관심 정보(`InterestProfile`)가 계정에 합쳐진다

> PROPOSED: 구현 순서는 구글 → 이메일 → 카카오. 이메일 인증 메일은 별도 SMTP로 보낸다(SMTP 종류는 구현 때 결정). 카카오는 비즈 앱 전환과 이메일 동의항목 심사가 필요하다.

### Requirement: FR-ACCT-05 회원 탈퇴
시스템은 사용자가 탈퇴할 수 있게 하고, 탈퇴하면 법령상 보관해야 하는 결제 기록(`PaymentRecord`)만 분리 보관한 뒤 나머지 계정 정보와 개인정보를 지워야 한다(SHALL).

#### Scenario: 탈퇴 확인
- **WHEN** 사용자가 지워지는 정보(관심 정보, 관심 기업, 공고, 경험 카드, 연결 결과, Prompt Kit)와 남은 패스가 사라진다는 안내를 보고 탈퇴를 확인하면
- **THEN** 결제 기록만 분리 보관되고, 나머지 데이터와 업로드 파일이 지워지고, 로그아웃된다

#### Scenario: 탈퇴 취소
- **WHEN** 사용자가 안내를 보고 확인하지 않으면
- **THEN** 아무것도 지워지지 않는다
